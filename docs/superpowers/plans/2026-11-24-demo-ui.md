# Demo TUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a full-screen terminal UI that shows the live edge simulation and exposes the existing demo commands as labelled actions on the `demo-ui` branch.

**Architecture:** Extract the CLI's session assembly into a shared `build_session()` so the TUI drives the exact same `EdgeRuntime`. Add read-only view helpers, then a pure snapshot/render layer that a curses loop paints. Every key routes through `EdgeRuntime.handle_command()`; the UI never touches the store or publishers directly.

**Tech Stack:** Python 3, stdlib `curses`, `argparse`, `logging`, existing `pytest` suite.

**Spec:** `docs/superpowers/specs/2026-11-24-demo-ui-design.md`

## Global Constraints

- Work on branch `demo-ui`; do not merge into `main`.
- No third-party dependencies. The test interpreter is `/tmp/opencode/post-flood-edge-venv/bin/python`.
- Default transport stays `--dry-run`; `--mqtt` stays opt-in.
- No new commands, payload keys, scenarios, alarm thresholds or ThingsBoard configuration.
- `logs/edge.log` must keep receiving the same log lines as the CLI.
- Shutdown order stays: stop runtime → disconnect publishers → close store → remove/close handlers → restore curses.
- Every task ends with a commit.

## Review Focus

- **Terminal smaller than 80×24:** must exit with a readable message, not crash or leave the terminal raw — pinned by `test_rejects_small_terminal` in Task 4 via `check_terminal_size()`.
- **Telemetry before first tick / powered-off or stuck node:** must show `—` placeholders and explicit `[FAULT]`/`[OFF]` badges rather than `KeyError` or stale values — pinned by `test_snapshot_with_empty_values` and `test_snapshot_badges` in Task 3.
- **Log flood during a long demo:** the on-screen log tail must stay bounded and show the newest lines — pinned by `test_capture_handler_is_bounded` in Task 4.
- **No colour support:** severity must remain readable as text — pinned by `test_render_includes_severity_text` in Task 3.
- **Blocked MQTT publish during shutdown:** must not close the store or disconnect a publisher before `runtime.stop()` — pinned by the existing `test_cli_shutdown_order` in Task 2 (full suite regression) and by preserving `cli.main()`'s cleanup sequence.
